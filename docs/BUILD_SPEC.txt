This is the single source of truth for building an internal Learning Management System
(LMS) with React, Node.js and Supabase. Hand it to an AI coding agent one phase at a
time (Section 8) and it has everything needed to build, with no guessing.
1. How the AI must use this doc
Rules for the AI builder (non-negotiable):
1. 
Build only what this doc specifies. If something is ambiguous, pick the simplest option,
write the assumption in 
docs/ASSUMPTIONS.md
, and continue.
2. 
Build one phase at a time (Section 8). Do not start the next phase until the current
phase's acceptance checklist passes.
3. 
Use TypeScript everywhere (frontend and backend). Strict mode on.
4. 
Validate every request body with Zod. Never trust client input.
5. 
All authorization is enforced on the server (Express middleware plus Supabase RLS).
Hiding a button in React is never security.
6. 
No public sign-up anywhere: no sign-up page, no sign-up endpoint. Users are created
only by an Admin.
7. 
Never hardcode secrets. Read all config from environment variables; commit
.env.example
 only.
8. 
Every list endpoint is paginated. Every table has 
created_at
; mutable tables have
updated_at
.
9. 
Write at least one test per endpoint (happy path plus one permission-denied case)
using Vitest and Supertest.
10. 
Every screen needs loading, empty and error states.
Definition of done for any feature:
 migration applied, API implemented and validated, RLS
policy written, UI built (responsive, accessible), tests passing, acceptance criteria in the
feature spec ticked.

Storage, Realtime). The browser uses Supabase directly only for Realtime chat
subscriptions; everything else goes through the API.

Auth flow:
1.

 (email, password). The API calls

,

2. 
React stores the session in memory plus a refresh token in an httpOnly cookie
(preferred) and attaches 
Authorization: Bearer <access_token>
 to every call.
3. 
Express middleware 
requireAuth
 verifies the JWT with Supabase, loads
profiles.role
, and attaches

A user with
